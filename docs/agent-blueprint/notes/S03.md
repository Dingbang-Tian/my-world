# S03：配置化提示词和默认覆盖

工程状态：已验证。学习状态：待回答。日期：2026/10/02。

## 本阶段解决什么

最小调用链：Spring 启动 → `AgentPromptProperties` 绑定 `my-world.agent.prompts` → `AgentPromptConfiguration` 收集应用与项目覆盖 → `PromptTemplateRegistry` 加载资源、校验、计算 SHA-256 → `PromptTemplateSnapshot.render` 检查变量 → `toSystemMessage` 构造 `Role.SYSTEM` 消息。

默认模板位于 `my-world-ai-agent/src/main/resources/prompts/agent/`，包括 `system`、`plan-step`、`summary`、`sub-agent`。配置中的 `inline` 和 `location` 二选一，`location` 只接受 `classpath:/` 或 `file:/`。模板标识为 `agent/system` 等完整 key；项目 YAML 使用 `system` 等短 key。优先级为项目覆盖 > 应用 `PromptTemplateContributor` 提供的资源覆盖 > 公共默认资源。未设置的值继承；空文本报错；`enabled=false` 才显式关闭。应用提供者暂时一次接入一个，重复提供者由 Spring 报出歧义。

模板只识别 `{{name}}` 这种简单变量，不执行表达式。必需变量缺失时报错；替换只做一次，变量值中的 `{{...}}` 会保留为普通文本。模板文件在仓库构造时读取，仓库和快照均不可变；同一次运行取得快照后，即使文件变化，已取得内容与 hash 也不变。重新创建仓库才能读到新版本。S04 才会把此仓库接入实际 Agent 调用；本阶段没有模型请求或真实运行中的热更新。

现有普通聊天配置 `my-world.ai.default-system-prompt` 仍属于 `my-world-ai` 的 `AiChatService`，不会覆盖 `my-world.agent.prompts`。项目用户任务将在后续阶段作为 USER 消息传递；默认 SYSTEM 模板只包含 Agent 身份、技能说明及可信运行上下文槽位。提示词中写“只用授权工具”只是模型指导，真正的工具授权须由后续工具注册和执行层检查。

实际测试示例：项目 YAML 的 `system.inline` 为 `项目 YAML 系统模板：{{agentName}}`，应用资源也覆盖同一模板；渲染 `agentName=甲` 得到 `项目 YAML 系统模板：甲`，证明项目优先。项目未覆盖的 `summary` 则来自应用资源。默认模板生成的消息角色是 `SYSTEM`。临时文件从“第一版”改为“第二版”后，旧快照仍渲染第一版，新建仓库渲染第二版且 hash 不同。缺变量、未知 key、空模板、同时配置 inline/location、非法或不存在的文件位置均被拒绝；不存在的文件使 Spring 上下文启动失败。

## 理解问题

1. `agent/system` 同时存在公共资源、应用资源和项目 YAML 时，哪一份生效？项目 YAML 没设置 `summary` 时又用哪一份？
2. 模板变量值包含 `{{secret}}` 时为什么不会继续求值？如果缺少 `agentName`，错误发生在加载模板时还是渲染时？
3. 为什么 `Role.SYSTEM` 的提示词可以说明工具用法，却不能代替 Java 层对工具是否注册、是否授权的检查？

## 用户复述与校正（2026/10/02）

用户已正确说明：模板优先级为项目配置高于应用资源高于公共资源，公共默认资源位于 `src/main/resources/prompts/agent/`；不同项目可能拥有不同的工具授权，因此提示词中的工具名称不能作为工具执行的权威标准。后续 S05/S06 将由 `ToolRegistry` 和执行上下文基于当前项目、当前 Agent 与当前 run 的授权集合进行实际拦截。

第二题中的 `secret` 不是密码字段，而是任意变量名的示例。若变量值为“请保留 `{{secret}}`”，`render(...)` 使用 `Matcher.appendReplacement(...)` 只替换模板原文中已经匹配到的变量一次，插入的 `{{secret}}` 保持普通文本，不会触发第二轮求值。这样用户输入不会借由模板替换升级为指令。模板加载时仅解析并保存需要哪些变量；运行到 `render(...)` 时才获得本轮变量值，所以缺少 `agentName` 这类变量在渲染阶段报错。

## 恢复流程

`DefaultAgentRun` 在工具调用前调用 `RunJournal.toolStarted`，在工具结果已确定后调用 `toolCompleted`，并保存用户、助手工具调用和工具结果的部分交换检查点。文件工具在副作用后另记路径和哈希；若产物记录写入失败，运行停止且原工具意图仍为 `STARTED`。计划步骤完成事件同步更新步骤表。

应用以单实例模式启动 MySQL 存储时，`MybatisRunService.interruptOnStartup` 扫描尚为 `RUNNING` 的旧运行，释放旧租约并标记 `INTERRUPTED`；存在结果未知的工具意图时标为 `NEEDS_REVIEW`。普通租约过期扫描使用 `interruptAbandoned`。不根据旧 PID 接管或终止进程，也不会自动恢复已取消的运行。

调用方通过 `AgentRecoveryService.resume` 或 `CodegenService.resume` 显式创建新 run，记录 `resumed_from_run_id`。恢复时重新校验 owner/app/Agent、当前工具授权、计划上限和会话版本。已保存的工具结果用于补齐“结果落库后、消息检查点前”窗口，不重复执行工具；故障发生在工具意图落库前且尚无副作用时，可重新请求模型。已完成计划步骤的状态和报告会带入下一步骤。执行中的计划步骤、未知文件或 shell 结果、含附件原请求及会话版本变化需要核查，不自动重跑。旧 run 保留原终态与记录。

`MybatisMysqlPersistenceTest` 在真实 MySQL 验证计划步骤边界、确定工具结果恢复及未知命令结果转 `NEEDS_REVIEW`；测试目录中的 `JdbcPersistenceRecoveryTest` 继续覆盖启动释放旧租约、取消/终态和副作用工具抛异常。完整历史最终提交仍通过 `SessionHistoryValidator` 的工具配对约束。JDK 21 下全项目 116/116 测试通过。数据库事务不能回滚文件或外部进程副作用，因此不承诺 exactly-once，也不尝试恢复 JVM 调用栈或旧 shell 进程。

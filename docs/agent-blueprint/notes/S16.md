## 调用链

可信模型配置 `modelId → protocol` → `RoutedModelGateway.generate` → 单次适配器编码消息、工具和选项 → HTTP SSE → 增量事件、用量、唯一 `ModelTurn` → 既有 `DefaultAgentRun` 执行工具并续问。`OpenAiChatGateway` 继续服务旧配置；Responses 和 Anthropic 使用 `MultiProtocolGateway`。适配器不执行 Java 工具，也不持有会话级可变参数。

Responses 以 `input` 项编码系统/用户/助手消息、`function_call` 和 `function_call_output`；聚合 `response.output_text.delta`、工具参数增量及 `response.completed`。Anthropic 将系统提示词放在顶层 `system`，使用 `content` 块表示文本、`tool_use`、`tool_result` 和图片；聚合 `content_block_*`、`message_delta`、`message_stop`。工具参数在完整 JSON 校验后才进入 `ToolCall`。实际断流、未完成事件或 HTTP 错误只产生错误终态。

推理历史使用协议元数据保存：Chat 的 `reasoning_content`、Anthropic 的 `thinking`/`thinking_signature`、Responses 加密 `reasoning_item_json`。Chat 的 `reasoning_content` 回传和 Qwen `chat_template_kwargs.enable_thinking`、Anthropic 无签名旧推理历史的回传均通过模型实例显式配置，不通过模型名称推测。`ModelOptions` 的 `thinkingEnabled`、`reasoningEffort` 等逐次覆盖，调用之间不共享可变状态。Responses 的推理强度映射到 `reasoning.effort`；Anthropic 的 low/medium/high 映射到 1024/2048/4096 token 预算，若 `max_tokens` 不大于预算则本地拒绝。

应用配置例子（接口地址均为完整路径，密钥从环境注入）：

```yaml
my-world:
  ai:
    chat:
      enabled: true
      models:
        main-responses:
          protocol: responses
          provider-id: openai
          endpoint: https://api.openai.com/v1/responses
          model: your-response-model
          api-key: ${OPENAI_API_KEY}
          image-enabled: true
          reasoning-enabled: true
        main-anthropic:
          protocol: anthropic
          provider-id: anthropic
          endpoint: https://api.anthropic.com/v1/messages
          model: your-anthropic-model
          api-key: ${ANTHROPIC_API_KEY}
          image-enabled: true
          reasoning-enabled: true
```

## 附件能力矩阵

| 协议 | 已实现输入 | 明确拒绝 |
|---|---|---|
| OpenAI Chat | 启用图片能力后，USER 的 JPEG/PNG/GIF/WebP HTTPS URL 或有界内存图片 | 未启用图片、非 USER 图片、音频/视频/文档、其他 MIME |
| OpenAI Responses | 启用图片能力后，USER 的同上图片来源 | 同上 |
| Anthropic Messages | 启用图片能力后，USER 的 JPEG/PNG/GIF/WebP 有界内存图片，以 base64 source 发送 | 远程图片 URL、音频/视频/文档、其他 MIME |

`MediaContentBlock` 的内存内容限制为 1 MiB，构造时验证 MIME 和来源；更大媒体应交给后续附件存储引用方案。`AgentRequest` 可带附件，用户文本与附件按序进入 USER 消息；`SessionExportCodec` 在现有 schemaVersion 1 增加可选 `contentBlocks` 数组以保留混合内容顺序，同时继续导入旧 `texts` 格式。`ContextAssembler` 将附件按保守大小计入窗口估算。

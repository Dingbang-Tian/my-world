## 调用链与边界

`DefaultAgentService.prepare` 固定 `agent/summary` 模板快照。`DefaultAgentRun.execute` 独占会话并读取包含完整历史、版本和摘要的同一快照。首轮模型请求前，`ContextAssembler` 组装系统提示、摘要、未覆盖历史和最新用户输入；达到轮次或估算 Token 阈值时，运行时以无工具模型请求分块摘要完整交换。全部分块成功后，`Session.updateSummary` 在版本和旧覆盖位置匹配时原子更新摘要与覆盖消息数。原始历史不删除。后续工具回合在每次请求前再检查窗口；当前尚未完成的工具交换不能拆分或摘要，超过窗口即返回明确限额错误。

摘要只包含已完成的原始交换。下一次摘要请求加入上一版摘要和新增完整交换，不再加入已覆盖的原始消息。最新用户输入始终在本轮消息末尾；摘要失败或超长时，当前用户交换不提交，原始历史与已提交摘要保持原样。一个运行中的多块摘要先在本地暂存，全部成功后才提交覆盖位置。摘要请求计入模型回合、输出字符、全局时限和取消令牌；有供应商用量时按独立 `runId:summary:n` 计入 USAGE 和最终结果。成功覆盖后发布 `MEMORY_COMPRESSED` 事件。

## 配置与估算

`AgentDefinition` 可传 `ContextPolicy(windowTokens, triggerRounds, triggerTokens, reserveOutputTokens, maxSummaryTokens)`。默认值依次为 `32768, 20, 24576, 4096, 1024`。Codegen 可通过 `my-world.codegen.context-window-tokens`、`summary-trigger-rounds`、`summary-trigger-tokens`、`reserve-output-tokens` 和 `max-summary-tokens` 覆盖。摘要模板走既有提示词仓库，项目可覆盖 `my-world.agent.prompts.summary`；模板必须提供 `{{conversationText}}`。

输入估算按 UTF-8 字节、每条消息及工具调用的固定协议开销、工具定义和已知元数据求和；它是保守的本地估算，并非供应商 tokenizer 的精确计数。`windowTokens` 应按实际模型能力配置并留余量。正常输入容量为窗口减去回答预留与本次 `maxCompletionTokens` 中较大者。摘要请求另外预留 `maxSummaryTokens`。单个完整交换放不进摘要窗口，或摘要加最新输入仍放不进正常窗口时，返回 `CONTEXT_WINDOW_EXCEEDED` 说明，不静默丢弃消息。

## 消息示例

原始历史：`USER(目标一) → ASSISTANT(回答一) → USER(调用工具) → ASSISTANT(call c1) → TOOL(c1 结果) → ASSISTANT(回答二)`。摘要覆盖位置为 6 后，本轮模型消息为 `SYSTEM(可信指令) → SYSTEM(历史摘要) → USER(最新输入)`。会话查询与导出仍含前述六条原始消息。若之后有完整交换，下一请求为 `SYSTEM → SYSTEM(摘要) → USER/ASSISTANT(未覆盖交换) → USER(最新输入)`。

导出 JSON 继续使用 schemaVersion 1，新增可选 `memorySummary.text` 与 `memorySummary.coveredMessageCount`。无摘要的 S09 JSON 可以导入；导入校验覆盖位置是完整交换边界，恢复时仍绑定当前可信 Agent 定义与当前上下文策略。会话 JSON 不保存模型权限或可信阈值。

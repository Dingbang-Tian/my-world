# S02：单次模型消息与假模型

工程状态：已验证。学习状态：已掌握主线。日期：2026/10/02。

## 本阶段解决什么

最小调用链：`ModelRequest(SYSTEM/USER 消息)` → `ModelGateway.generate` → `TextDelta("O")` → `TextDelta("K")` → `TurnCompleted(ModelTurn(ASSISTANT "OK", STOP))`。前两条事件供界面实时展示，最后一条携带完整助手消息。此阶段只规定模型“一轮生成”的输入和输出，还没有 Agent 循环、工具执行、会话记忆或真实供应商适配器。

对照 Agent4J 的 `LLMModel.ask(...)`、`LLMResult.execute()/get()`、`Message.fromUser/fromAssistant/appendToolCall` 及 `MessageToolCall/MessageToolResult`：参考实现将模型调用与后续工具处理放得较近；这里先把模型一轮返回的数据同 Java 工具执行对象分开。原项目的 `Message.fromUser` 不能直接代表系统角色，因此新契约显式保留 `Role.SYSTEM`。本阶段没有复制参考项目源码。

## 关键代码与设计取舍

- `my-world-ai-framework/.../model/`：`Message` 有 ID、角色、文本内容块、工具调用、工具结果及协议元数据。`model/content/ContentBlock` 是内容块接口，`model/content/contentImpl/TextContentBlock` 是独立的文本实现；`ToolCall` 保留 `callId`、工具名和完整参数 JSON；`ToolResult` 留出工具执行结果的数据形状，`ToolResultStatus` 独立表示状态，但本阶段不执行工具。
- `my-world-ai-framework/.../api/`：`ModelRequest` 是一次请求的消息快照；`ModelGateway.generate` 返回冷 `Flux<ModelEvent>`；`api/event/ModelEvent` 是事件接口，`api/event/eventImpl/TextDelta` 和 `TurnCompleted` 是独立实现，后者包含完整 `ModelTurn` 与结束原因。`ModelEventStreams.requireCompleted` 按每次订阅检查终态：缺失、重复或终态后继续发事件都报错，源流错误继续传播。
- 测试目录中的 `ScriptedModelGateway` 只在订阅时执行本地脚本，可返回文本、工具调用或错误；它不连接 LLM 服务器。

新增数据类采用普通 `final class`、私有 `final` 字段和显式校验构造器；Lombok `@Data` 统一生成 getter、值比较及 `toString`。由于字段全部是 `final`，不会生成 setter；显式构造器仍负责校验和防御性复制。未使用 `record`。`final class` 不是普通类的编译要求，但这些对象是不可变值快照，禁止子类改变读取或比较行为，也保持原 `record` 不能被继承的语义；需要扩展时实现 `ModelGateway`、`ModelEvent` 或 `ContentBlock` 接口。字符串空白与集合空判断使用 `my-world-common` 的 `StringUtils`、`CollectionUtils`。集合在构造时复制并包装为不可修改视图，避免请求或消息被调用者事后修改。S02 契约现在位于独立 `my-world-ai-framework` 普通 JAR 中，该模块编译依赖不包含 Spring AI。项目仍按 Java 21 编译；“Java 8 写法”指这些类的数据建模和测试写法。

## 验证和实际轨迹

命令：在仓库根目录以本机 JDK 21 运行 `mvn -q test`。结果：`ModelGatewayContractTest` 4/4、`ConfigSecretCipherTest` 9/9、`ModuleAssemblySmokeTest` 1/1，共 14/14 通过。

假模型的实际输出：

```text
请求：USER「只回复 OK」
事件：TextDelta("O") → TextDelta("K") → TurnCompleted(ASSISTANT「OK」, STOP)
订阅次数：1
```

另一测试保留 `SYSTEM` 消息和 `ToolCall(callId="call-1", name="add", argumentsJson="{\"a\":2,\"b\":3}")`，其结束原因为 `TOOL_CALLS`。错误脚本通过 Reactor 错误通道传播；缺少完整回合、重复完整回合分别被检测。

上述只证明本地契约与假模型流程。没有真实 DeepSeek 等 LLM 连通验证，也没有执行 `add` 工具；完整助手消息尚未写入会话历史，历史管理将在后续阶段实现。

## 用户复述与校正（2026/10/02）

用户理解为：`ModelGateway` 是单轮模型调用入口，`ModelRequest` 携带消息列表和模型信息，调用以流式方式返回，并由消息角色和回合结束原因表达结果；当前还没有 Agent harness、工具循环或会话记忆。这条主线正确。

需要补充两点：`ModelGateway` 本身不记录历史，`Message` 保存角色，`ModelTurn.finishReason` 保存结束状态；`ModelRequest` 当前只有 `modelId` 和消息列表，工具描述、调用级选项等会在后续阶段扩展。`TextDelta` 只用于实时展示，完整助手消息由 `TurnCompleted` 携带，当前也没有持久化层。

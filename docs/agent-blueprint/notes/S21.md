## 从失败任务定位问题

请求进入 `DefaultAgentService.prepare` 后固定定义、会话和模板；`DefaultAgentRun.execute` 写入运行记录并开始模型循环。默认 INFO 日志依次记录 `agent_run event=start`、每轮 `agent_model`、工具的 `agent_tool` 阶段与最终 `agent_run event=finish`。同一运行使用 `runId`；父子运行共用根 `traceId`，子级额外记录 `parentRunId`。从最终 `errorCode` 和模型、工具阶段可以判断失败落在配置、模型、工具参数、工具执行、持久化、取消或限额哪一层。事件和检查点仍由现有 `RunJournal` 保存，可按 `runId` 查完整运行历史。

`RunAuditInterceptor` 集中观察所有工具阶段（包括计划和子 Agent 内部工具），用 `callId` 关联准备、调用和终态，记录 `durationMillis`、结果状态和错误码。日志不记录工具参数、工作目录、工具结果或异常原文。普通模型和摘要模型分别记录调用耗时；运行开始日志保存模型标识、模板 hash、实际生成选项和主要限额的安全配置快照。请求标识仅写 SHA-256，避免原始请求标识带入敏感文本。`runId` 对应启动与终态日志，便于追溯配置。

`usageStatus=unknown` 表示供应商没有报告用量，token 数字段为 `null`；`partial` 表示本运行只有部分模型调用报告了用量；`reported` 表示本运行调用均报告了用量。原有 `usageByModelCallId` 只在唯一调用第一次报告时汇总，父级接收子级用量也按调用标识去重。Token 合计是已报告用量，不把缺失用量假装成零。父级最终合计包含已报告的子级用量；若子级供应商遗漏用量，须查看该子运行的 `usageStatus`。

## 调试开关和脱敏

默认不记录模型请求正文或 SSE 分片。仅在可信进程启动参数设置 `-Dmyworld.agent.debug=true` 时，`DefaultAgentService` 会通过 `SafeModelDebugGateway` 包装模型网关，DEBUG 日志只记录消息和工具数量、非敏感生成选项、事件类型及随机调用标识。请求文本、密钥、工具参数、流式文本和错误原文始终不写调试日志；内容字段明确显示 `[REDACTED]`。直接使用模型网关而不经过 Agent 服务时，可显式使用 `SafeModelDebugGateway.whenEnabled(delegate)`。

该开关在服务构造时读取，变更后需要重新创建服务；还需将 `SafeModelDebugGateway` 的日志级别设为 DEBUG 才会输出调试记录。日志格式为稳定 `key=value` 字段，可由部署侧收集和筛选。审计策略集中在拦截器，新增工具审计字段时在此处扩展，避免在每个工具实现中复制日志逻辑。

## 边界与理解问题

Token 限额在生成前依靠上下文 token 估算、`maxCompletionTokens` 和运行预算控制；流式过程中还有字符上限、截止时间和取消信号。供应商的实际 token 用量通常在调用结束或流尾报告，因此实时精确控制仍依赖供应商支持，不能用事后用量代替生成中硬限制。

模型调用失败通常可以重新请求，但要考虑重复输出和费用；工具调用可能已写文件或执行命令，结果未知时重试可能重复副作用。S19 的检查点把未知工具结果标记为 `NEEDS_REVIEW`，只有已确认的安全边界允许显式恢复。

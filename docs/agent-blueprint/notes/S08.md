## 本阶段解决什么

一次运行的实际链路是：`prepare → subscribe → execute → 全局截止时间与预算检查 → ModelGateway.generate → 增量事件 / 完整 ModelTurn → 顺序工具 → 唯一终态 → 释放会话与网络资源`。`AgentRun.cancel()` 可以在执行前、模型流中或工具执行中调用，重复调用幂等。完成、失败、取消、超时、超预算由同一运行状态竞争；迟到模型回调不能覆盖已确定终态，也不会在终态之后启动下一工具或补写消息。

`AgentLimits` 来自可信 `AgentDefinition`，默认最多 8 个模型回合、32 次工具调用、65536 个 UTF-16 输出字符、512 条事件及 120 秒全局时限。旧的 `maxModelTurns` 构造器仍可使用。`ModelExecutionContext` 把剩余输出额度、截止时间和共享 `CancellationToken` 交给单次网关；`ToolExecutionContext.checkActive()` 让工具能在副作用前后主动检查。工作线程在取消时受到中断，Chat 网关也关闭正在读取的 SSE 流。全局计时器独立于模型和工具工作线程，因此无回调的模型调用也能结束 `getResult()`。

事件历史和每个观察者的待处理队列都有限。`subscribe(listener, afterSequence)` 从最后已消费的序号之后继续；历史缺口抛出带 `EVENT_HISTORY_GAP` 与首个可用序号的 `AgentEventException`。过慢的观察者收到 `SLOW_CONSUMER`，观察者抛错收到 `LISTENER_FAILURE`。回调在独立事件执行器上串行派发，不阻塞模型与工具运行。

单次 Chat 网关在读取 SSE 时限制单行、协议总量以及文本、推理与工具参数的聚合大小；无 `finish_reason` 或 `[DONE]` 的 HTTP 200 流仍失败。`401/403` 归为 `CONFIGURATION_ERROR`，`400/422` 归为 `INVALID_REQUEST`，其他 HTTP 或流协议故障归为 `MODEL_ERROR`；未注册模型是配置错误，未支持的消息能力是 `UNSUPPORTED_CAPABILITY`。普通 Java 工具参数和执行错误继续生成可供模型修正的 `TOOL` 结果；取消、超时和预算停止不会伪装为普通工具错误。

## 本地验证与事件轨迹

使用本机 JDK 21 运行 `mvn -q -o clean test`，全项目 55/55 通过，S08 新增 10 个测试。`AgentRunControlTest` 使用本地脚本模型和 Java 工具，覆盖完成后迟到错误、重复取消、模型取消传播、取消第一工具后不执行第二工具、无回调超时、工具与输出额度，以及重复 usage 事件仅累计一次。`AgentEventPublisherTest` 覆盖历史缺口、续订和慢消费者。`OpenAiChatCancellationTest` 仅在 `127.0.0.1` 启动本地 HTTP fixture，验证打开中的 SSE 可被取消，以及超长模型增量被限制。原 S07 的 HTTP 200 断流和协议回归继续通过。

示例轨迹（本地假模型）：

```text
USER → ASSISTANT(call c1, c2) → TOOL c1 开始
用户取消 → CANCELLED 终态 → 取消令牌与工作线程收到停止信号
TOOL c2 未启动；Future 已完成；迟到回调不能改成 FAILED
```

示例轨迹（本地 HTTP fixture）：

```text
HTTP 200 → SSE 文本增量 → 连接保持打开
取消令牌触发 → 关闭响应流 → 网关错误回调为 CANCELLED
```

参考实现的 `LLMResult.fail` 在 Future 完成竞争中忽略迟到错误；三个模型完成分支还需要区分主动关闭连接与真实断流，`StreamCompletionTest` 用 HTTP 200 的不完整响应验证此区别。本项目保持单次模型适配器与唯一 Agent 循环：协议层不执行 Java 工具。全局截止时间统一由 Agent 状态机裁定，HTTP 请求时限取 90 秒与剩余时限中的较短值。

## 取舍与后续

运行 Future 和终态事件在取消时先完成，然后向网络及受管工作线程传播清理，避免资源关闭阻塞调用方取得结果。工具取消是协作式的：已发生的外部副作用不能被 Java 中断回滚；S12 的命令进程清理和 S19 的副作用检查点仍需单独实现。自定义异步 `ModelGateway` 也必须遵守传入的取消令牌；本阶段只实际验证了自研 Chat 网关。当前输出额度按字符计数，是独立的内存保护，不能替代供应商 token 配额或未来 S15 的上下文窗口估算。未使用真实供应商凭据，未声称远程连接兼容性已验证。

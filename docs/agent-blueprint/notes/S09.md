# S09：会话历史、隔离与导出恢复

工程状态：已验证。学习状态：待回答。日期：2026/10/03。

## 本阶段解决什么

`AgentDefinition` 是服务端可信配置，`Session` 是 owner/app/Agent 归属下的多轮状态，`AgentRun` 只代表一次输入到唯一终态。`SessionRepository` 抽象存储；当前 `InMemorySessionRepository` 在同一进程内原子管理会话。模型请求读取历史与版本的同一快照，成功时一次性提交 `USER → ASSISTANT → TOOL → ASSISTANT` 等完整交换并增加版本。取消、超时、失败及不完整工具交换不会写入历史。会话执行独占，第二次并发执行返回 `SESSION_BUSY`；仓库提交还检查版本，冲突不会覆盖新历史。

`AgentRequest` 新增可信 `ownerId` 与单次 `ModelOptions`；旧构造器为了兼容原调用方，将 appId 同时作为 ownerId。多用户入口必须从已认证上下文传入 ownerId。`AgentSessionService` 提供空会话创建、历史读取、导出和导入。会话级选项可由本次调用非空选项覆盖，模型实例默认值仍由网关处理。

导出 JSON 含 `schemaVersion=1`、会话身份、版本、会话级选项、文本与工具消息。仅保留续问所需的已知协议元数据；不包含 `ModelGateway`、工具实例、线程、Agent 定义或凭据。导入拒绝不支持的 schemaVersion、错误归属、重复 sessionId 和不完整工具配对，再绑定当前服务已注册的 AgentDefinition。因此导入的 JSON 不能新增可执行工具权限。当前格式只支持文本内容块；未来多模态需提升 schemaVersion 并增加迁移测试。

## 验证

本机 JDK 21 下运行 `mvn -q -o clean test`，全项目 58/58 通过。S09 的 `AgentSessionServiceTest` 新增 3 个测试：不同 owner 的历史及温度隔离；导出后新服务导入、语义相等及追问；配对工具历史与版本冲突；忙会话导出拒绝、第二运行忙错误，以及取消后历史为空。S06 `AgentToolLoopTest` 继续验证真实运行产生的多工具调用和结果被下一轮完整复用。测试只使用本地假模型和本地 HTTP fixture，没有真实供应商调用。

## 取舍与后续

当前内存仓库无法跨进程重启自动恢复；显式 JSON 导出/导入可以跨服务实例继续会话。S18 才实现数据库仓库，S15 处理摘要与上下文选取，S19 处理副作用后的未知状态。导出只保存已完成交换，因中断而已经发生的外部副作用不能由会话 JSON 自动撤销。

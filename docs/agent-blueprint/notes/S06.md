# S06：唯一 Agent 循环

工程状态：已验证。学习状态：待回答。日期：2026/10/02。

## 本阶段解决什么

最小调用链：`AgentService.prepare` 根据可信 `AgentDefinition` 选择工具和技能 → `AgentRun.execute` 发出带工具描述的第一轮 `ModelRequest` → 模型给出完整 `ASSISTANT` 工具调用 → `DefaultAgentRun.completeRound` 逐个调用 `ToolExecutor` → 用同一 callId 创建 `TOOL` 结果消息 → 再次调用同一 `ModelGateway` → 模型给出最终文本 → 一次性提交本次完整消息序列并结束运行。

`ModelGateway` 仍只负责单次模型请求。每一轮都新建 `ValidatingModelEventListener` 和 `RoundListener`，避免上一轮的 `ModelTurn` 误用于下一轮。工具执行放在配置的 JDK `Executor`，不会占用协议回调线程。每次请求收到固定的 `ModelToolDefinition` 列表：名称、说明和参数 JSON Schema；Java 工具实例与可信 `ToolExecutionContext` 留在 Agent 端。`AgentDefinition` 可指定直接工具、技能 ID 与最大模型回合数。`AgentSkill` 只聚合工具引用和说明；重复引用同一工具会去重。空工具／技能列表继续支持普通对话。

模型请求工具时先检查本轮是否达到上限。若已达到，就返回 `LIMIT_EXCEEDED`，不执行本轮的新工具调用；否则检查同一助手消息内的 callId 唯一，再执行工具。参数错误和未知工具被编码成 `TOOL` 错误结果，供模型下一轮修正。成功完成后，进程内历史保存 `USER → ASSISTANT(call) → TOOL(result) → ASSISTANT(answer)` 的原始顺序。失败运行当前不提交未完成交换；外部副作用的恢复和检查点属于 S19。

## 本地验证与消息轨迹

显式使用本机 JDK 21 运行 `mvn -q clean test`，全项目 40 个测试通过；S06 新增 4 个测试，另调整 S04 的未授权工具测试以符合新行为。测试使用本地 scripted 假模型和纯 Java 加法工具，没有真实模型或远程协议调用。

```text
请求 1: SYSTEM, USER("计算两组加法"); tools=[add]（技能和直接授权重复时只发送一次）
模型 1: ASSISTANT(call-1:add(2,3), call-2:add(4,5))
本地工具: call-1 → 5；call-2 → 9
请求 2: SYSTEM, USER, ASSISTANT(call-1,call-2), TOOL(call-1=5), TOOL(call-2=9)
模型 2: ASSISTANT("5 和 9")
下一用户请求: SYSTEM, USER, ASSISTANT(call-1,call-2), TOOL(call-1=5), TOOL(call-2=9), ASSISTANT("5 和 9"), USER
```

事件从 1 连续编号：`call-1 PREPARING → CALLING → COMPLETED → call-2 PREPARING → CALLING → COMPLETED → COMPLETED`。参数缺少必填字段的另一个测试显示：工具执行次数仍为 0，`TOOL_VALIDATION_ERROR` 到达第二次模型请求，模型改用新 callId 和正确参数后工具才执行一次。未授权工具返回 `TOOL_NOT_FOUND`，模型可据此改答。重复 callId 在执行前失败；最大回合数为 2 时，第二轮继续请求工具得到 `LIMIT_EXCEEDED`，第二批工具不执行。

## 设计取舍

工具描述使用 framework 内的纯字符串 JSON Schema 契约，避免 framework 反向依赖 Agent 的 `ToolDescriptor` 或 Jackson。运行时负责授权与执行，模型适配器只看到可发送给供应商的说明。回合上限按模型请求次数计数，并在执行最后一轮返回的新工具调用前停止，避免执行后无法把结果再交给模型。

# S14：子 Agent 与父子上下文

## 调用链与行为

父模型调用 `create_sub_agent` 时，`DefaultAgentRun.startSubAgent` 先解析名称、职责、任务、可选上下文和 `toolIds`。`ToolRegistry.select` 只从父运行的授权快照中选取工具；省略 `toolIds` 时子级没有工具。子运行得到独立 `childRunId`、`childSessionId`、系统模板、用户任务与会话历史。父历史不会自动复制进去，子级模型的初始请求只含委派系统消息和任务 USER 消息。模型服务、不可变选项快照、授权工具实例和会话仓库可以共享，但模型消息与运行状态分别保存。

调用链为：父 Agent `create_sub_agent` → 可信工具子集和剩余预算校验 → `SubAgentRunner` 启动独立 `DefaultAgentRun` → 子级使用获授权工具并完成 → 父级取得带子运行标识和真实状态的配对 tool 结果 → 父模型继续总结。父级异步等待子级完成，执行器的工作线程不会被同步 `join` 占住；第一版仍按顺序运行子任务，不并行提交多个子 Agent。委派调用必须单独成批执行，混合工具批次会返回 `POLICY_DENIED`。

`AgentLimits.maxSubAgentDepth` 默认 2，根层为 0；达到上限时由程序拒绝下一层委派。子级模型回合、工具次数、输出字符与时限从父级剩余预算中收紧，并预留父级最终续问的一个回合和一部分输出空间。子级结束后，父级计入子树实际使用的回合、工具和输出；父取消传播到子运行的模型和工具。模型调用用 `runId:model:turnNumber` 标识，父级合并子树最终用量时按此标识去重，因此父 `AgentResult.usage` 汇总父子已完成调用而不重复计数。

子级失败、超限和其他终态都变成带 `SUB_AGENT_FAILED` 代码的父 tool 错误，内容包含子级 runId、sessionId、终态与原因；父模型可以据此解释后续处理。成功时只回传子级约定的最终文本，不把子级 assistant/tool 历史插入父历史。`create_sub_agent` 没有 `lastTask` 或 `lastCreatedAgent` 等跨运行可变中转字段。

代码生成应用通过 `my-world.codegen.sub-agent-enabled: true` 显式授权此能力，默认关闭。只读审查时即使父级已授权写文件，仍可给子级 `toolIds: ["view_file"]`；工具实例仍绑定父级可信工作目录，子级无法把目录权限扩大。

## 确定性轨迹

`SubAgentExecutionTest` 使用脚本模型，不调用真实供应商：父 `create_sub_agent` → 子 `read_probe` → 子回答“审查通过” → 父收到 `delegate` 对应的工具结果 → 父最终回答。子级首次模型请求恰好只有系统与用户两条消息，只看见 `read_probe`，没有父用户文本 `PRIVATE_PARENT`。父会话只保存委派调用、配对工具结果与父回答；子会话单独保存子 USER、assistant、read_probe 的 tool 结果和子回答。四次模型调用的模拟 token 总数为 2 + 3 + 4 + 5 = 14，父最终用量为 14。

同一测试类还验证：未授权工具不能因子级申请而获得；深度为零或达到已配置最大层数时拒绝；子级模型失败可由父 tool 结果解释；父取消终止子级；父级已耗尽工具额度时子级不能重新获得额度；只有一个工作线程的执行器也能完成父子续接。

`CodegenServiceTest.delegatesReadOnlyCodeReviewToSubAgent` 在临时目录写入 Review.java，父级拥有文件写入权限但只把 `view_file` 交给子级；子级实际读取文件并报告无需修改，父取得结果。文件内容不变，父运行无文件修改产物。

参考对照：阅读 Agent4J 的 `CreateSubAgentTool`/`CreateSubAgentParam`、`AgentClientSession.executeSubAgentTool` 和 `AgentResultHandler.onSubAgent*`。保留独立子任务、结果回传和观察执行结果的能力；改为请求级参数与独立状态，不复制父全部工具，不使用工具实例上的 `lastTask` 通信。

## 验证与边界

JDK 21 下完整 `JAVA_HOME=/opt/homebrew/opt/openjdk@21 mvn -q test`：89/89 通过，零失败、零错误、零跳过。完整测试在允许 localhost HTTP fixture 的本机执行环境执行；S14 专项测试及代码生成测试也通过。没有真实供应商调用。

子会话目前跟随 S09 的进程内仓库，持久化与重启恢复在 S18/S19；父子用量指标和治理在 S21。当前子任务顺序执行，未宣称并行。工作目录约束来自固定的可信工具实例，不能把该目录配置本身误称为操作系统沙箱。

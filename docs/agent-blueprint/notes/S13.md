# S13：计划创建与顺序执行

## 调用链与行为

`DefaultAgentService.prepare` 只在可信 Agent 定义授权 `create_plan` 时提供该工具，并固定 `agent/plan-step` 模板快照。主模型调用 `create_plan` 后，`DefaultAgentRun.startPlan` 严格解析名称、目标、步骤和失败策略，依据 `AgentLimits.maxPlanSteps` 拒绝过长计划。`Plan`、`PlanStep` 保存不可变定义，`PlanRunner` 只保存当前运行的状态和结果；工具对象没有跨运行的 `lastCreatedPlan`。

每一步仍由同一个 `DefaultAgentRun` 调用 `ModelGateway.generate`，因此使用相同的模型选项、授权工具实例、取消令牌、截止时间、模型回合数、工具调用数和输出字符预算。程序从步骤模型可见工具列表中移除 `create_plan`，伪造的递归调用也会返回 `POLICY_DENIED`。步骤的系统模板只写执行规则；目标、当前步骤、前序结果和工具产物通过 USER 消息传入。下一步在本次运行内还能读取前一步完整工具轨迹。

步骤状态为 PENDING、RUNNING、SUCCEEDED、FAILED、SKIPPED。默认 STOP 会跳过失败后的步骤；只有显式 CONTINUE 才继续。模型错误、工具错误及工具实现声明的语义失败都会将该步标为 FAILED。`ExecuteCommandTool` 实现 `PlanStepOutcome`，按真实 `timedOut` 和退出码判断编译步骤是否失败；非零退出码仍以原工具结果送回模型供修正。计划结果按真实状态以 `create_plan` 的工具结果送回主模型。即使主模型随后输出“完成”，含失败步骤的 Agent 最终状态也是 FAILED，错误码为 `PLAN_FAILED`。

计划事件包含 PLAN_CREATED、PLAN_STEP_STARTED、PLAN_STEP_FINISHED、PLAN_FINISHED，并携带步骤序号、总数、状态及说明；它们与工具、用量和最终事件共用当前 run 的单调序号。父级取消或超时仍由唯一终态状态机传播到步骤模型和工具。

代码生成应用以 `my-world.codegen.plan-enabled: true` 显式授权计划工具，默认关闭。它继承同一文件和命令权限配置；计划开启时应用定义允许 24 个模型回合，单计划默认最多 6 步。公共 Agent 可通过可信定义自行授权 `CreatePlanTool` 并自定义 `AgentLimits.maxPlanSteps`。

## 确定性轨迹

`PlanExecutionTest` 的脚本模型：`create_plan → 步骤 1 artifact(HelloAgent.java) → 步骤 1 SUCCEEDED → 步骤 2 读到前一步摘要及工具结果 → 步骤 2 SUCCEEDED → PLAN_FINISHED → 主回答`。测试直接检查第二步的模型请求和计划事件。STOP 与 CONTINUE 场景让第一步模型失败，分别检查第二步 SKIPPED 或执行，同时计划与 Agent 都保持 FAILED。另检查步骤数上限、共享回合和工具预算、程序禁递归与父取消。

`CodegenCommandLoopTest.planCarriesCompileFailureIntoCorrectionStep` 使用临时工作目录、本地 `javac`/`java` 与脚本模型，未调用真实 LLM：

1. 计划第一步 `create_file` 写入缺少 `}` 的 HelloAgent.java。
2. 第二步 `execute_command` 实际运行 `javac`，退出码 1；即使模型给出文字总结，步骤仍为 FAILED。
3. 显式 CONTINUE 使第三步收到第二步的 FAILED 状态和编译输出；调用 `view_file` 获取 hash，`edit_file` 追加 `}`，重新运行 `javac`/`java`，退出码 0 并输出 HelloAgent。
4. 程序报告步骤状态为 SUCCEEDED、FAILED、SUCCEEDED，计划及最终 Agent 状态为 FAILED；文件和 class 产物、两次 `CommandReport` 可核对。

参考对照：阅读 Agent4J 的 `Plan`、`CreatePlanTool`/`CreatePlanParam`、`AgentClientSession.executePlanTool`/`buildPlanSystemPrompt`。保留 `create_plan` 的入口语义；改用不可变计划定义与每次运行独立状态，失败不再被“completed”文本覆盖，提示词限制与程序禁递归并用，未复制参考源码。

## 理解问题

1. `Plan` 和 `PlanRunner` 各自保存什么？为什么不能让一个共享的工具实例保存 `lastCreatedPlan`？
2. 即使步骤提示词写了“不要创建新计划”，为什么仍需要从工具列表移除 `create_plan` 并在执行时拒绝伪造调用？
3. 第二步 `javac` 退出码为 1、第三步修正成功时，为什么计划仍保留一个 FAILED 步骤？主模型说“全部成功”能改变最终状态吗？

## 本阶段解决什么

最小调用链：应用创建 `AgentDefinition` 与 `AgentRequest` → `AgentService.prepare` 固定 Agent、会话和系统模板快照 → 观察者注册 `AgentRun.subscribe(listener)` → `execute()` 将模型调用交给 JDK 后台执行器 → `ModelGateway.generate(request, listener)` 回调事件 → 模型收到 `SYSTEM + USER` → `TextDelta` 转为 Agent 文本事件 → `TurnCompleted` 的完整助手消息写入进程内会话 → `AgentRun.getResult()` 完成。同步便利入口 `AgentService.run(request)` 调用同一套准备与执行逻辑，并阻塞等待结果。

对外 API 位于 `my-world-ai-agent/.../agent/api/`：`AgentDefinition` 固定应用、Agent、模型和模板身份；`AgentRequest` 携带请求标识、可选既有会话 ID 与用户文本；`AgentService` 提供 `prepare/run`；`AgentRun` 提供 `getRunId/getSessionId/subscribe/getResult/execute`；`AgentEventListener` 接收 `onEvent/onComplete`；`AgentEvent` 携带运行和会话 ID、递增序号、时间、类型与载荷；`AgentResult` 携带终态、完整文本、模型结束原因、结构化错误及模板 hash。值对象使用普通 `final class`、`final` 字段和 Lombok `@Data`，没有使用 `record` 或内部类。

实现位于 `agent/runtime/`：`DefaultAgentService` 在构造时登记可信 Agent 定义，在 `prepare` 时解析项目所属会话与模板，不调用模型；`DefaultAgentRun` 在 `execute` 时只调用一次 `ModelGateway.generate`，并用 JDK 的 `ForkJoinPool.commonPool()` 在后台执行；`AgentEventPublisher` 保留最近 512 条事件、向多个 `AgentEventListener` 回放和发布事件；`ValidatingModelEventListener` 保障模型只产生一个完整回合；`DefaultAgentRun` 最终完成同一个 `CompletionStage`。`InMemoryAgentSession` 暂存成功完成的 USER/ASSISTANT 交换。下一轮请求使用 `SYSTEM + 已完成的历史 + 本轮 USER`。文本增量只作实时展示，不重复写入历史。会话同时只允许一条运行，忙时返回结构化 `SESSION_BUSY` 失败结果。模型错误也完成 Future 与事件监听器。模型提出工具调用时返回 `UNSUPPORTED_TOOL_CALL`，避免将未执行的工具误记为成功。

运行时向系统模板提供 Agent 名称、描述和运行标识等可信变量；用户输入仅构造 `Role.USER` 消息。`AgentResult.promptHash` 记录本轮实际使用的模板版本。当前公共服务可由消费模块用 `DefaultAgentService`、`ModelGateway`、`PromptRepository` 和定义集合显式创建；真实模型适配器及正式应用装配仍在后续阶段。

## 用户复述与校正（2026/10/02）

用户已指出原来的 `events()` 用于订阅事件、`execute()` 用于执行，这部分正确。根据“使用 Java 8 可理解实现”的新约定，公共 API 改为 `subscribe(listener)`：`prepare()` 会校验请求、解析 Agent 与会话、渲染并固定 SYSTEM 模板，但不会向模型传输请求；`DefaultAgentRun.execute()` 才组装 `ModelRequest`，并在后台调用 `ModelGateway.generate(request, listener)`。多个事件监听器注册的是同一个运行的有界事件发布器，不会各自触发模型调用。

用户回答“会话 list 添加 OK”抓住了完整回答，却遗漏了消息角色及用户输入。成功回合在历史中按顺序保存完整 `USER("只回复 OK")` 和 `ASSISTANT("OK")` 两条 `Message`，不保存两个 `TextDelta`，SYSTEM 在下一次运行时由模板重新构造。所以下一轮模型消息是 `SYSTEM + USER("只回复 OK") + ASSISTANT("OK") + 新 USER`。当前学习状态保持“待回答”，等待用户复述这两处边界。

## 推荐阅读入口（Java 监听器版）

从 `DefaultAgentRun.execute()` 开始读。它是一次运行真正开始的位置，能看到本轮请求如何由 `SYSTEM + 历史 + USER` 组装成 `ModelRequest`，以及为什么此时才占用会话并交给 `Executor` 后台执行。

按下面顺序跟读即可：

1. `DefaultAgentService.prepare()`：理解哪些内容在模型调用前固定，包括可信 `AgentDefinition`、会话、模板快照、SYSTEM 消息、runId 和 sessionId。
2. `DefaultAgentRun.execute()`：理解一次运行如何防止重复启动、如何检查会话忙、如何组装 `ModelRequest`。
3. `DefaultAgentRun.invokeModel()` → `ModelGateway.generate(request, listener)`：模型适配器只负责回调 `onEvent`、`onError`、`onComplete`。
4. `ValidatingModelEventListener`：确认回调序列必须包含一个 `TurnCompleted`，才能进入成功结束。
5. `DefaultAgentRun.onEvent/onComplete/onError()`：TextDelta 立即转换为 Agent 事件；完整助手消息暂存；onComplete 时才写入历史并产生最终 `AgentResult`。
6. `AgentEventPublisher` 与 `InMemoryAgentSession`：前者负责监听器回放和结束通知，后者负责保存完整 USER/ASSISTANT 历史并限制同会话并发。
7. `DefaultAgentServiceTest.executesOnceAndReplaysEventsToMultipleObservers()`：用本地脚本模型对照完整轨迹。它不连接真实 LLM。

一次成功运行的线程和数据路径：

```text
调用线程
  prepare() → AgentRun
  subscribe(listener)
  execute()
     └─ Executor 后台线程
          invokeModel()
          ModelGateway.generate(request, validatingListener)
          TextDelta → onEvent → AgentEventPublisher
          TurnCompleted → 暂存 ModelTurn
          onComplete → 写 USER/ASSISTANT 历史 → COMPLETED 事件 → AgentResult
```

# S12：命令执行及第一条生成闭环

## 调用链与行为

`CodegenConfiguration` 从可信配置读取工作目录、写权限、命令权限和环境变量白名单。`CodegenFactory` 只在 `command-enabled=true` 时注册 `execute_command`，并将命令技能加入 SYSTEM 提示词。模型提出命令后，公共 `ToolExecutor` 校验授权和参数，`ExecuteCommandTool` 解析相对 cwd、选择当前平台 shell、仅继承白名单环境变量，启动子进程并由独立线程持续消费合并输出。工具最多保留 16000 字节输出；命令时限从启动前计算，最长 60 秒。非零退出码作为实际命令结果返回给模型，供下一轮修正。父运行取消和超时会尝试终止进程树；进程枚举受系统限制时至少强制终止直接进程。

`CodegenService.artifacts(runId)` 返回文件变更，`commandReports(runId)` 返回本进程内的命令、cwd、shell、状态、退出码和有界输出。报告属于进程内记录，S18/S19 才处理持久化与不确定副作用恢复。`cwd` 只是进程工作目录，不限制 shell 访问其他路径；命令开关默认关闭，只面向可信本地工作区。

启用示例：

```yaml
my-world:
  codegen:
    enabled: true
    model-id: codegen-main
    workspace: /absolute/path/to/trusted-workspace
    write-enabled: true
    command-enabled: true
    command-environment-allowlist: [PATH, JAVA_HOME, LANG, TMPDIR]
```

## 确定性轨迹

`CodegenCommandLoopTest` 使用脚本模型及 JUnit 临时目录，不调用真实 LLM：

1. 模型调用 `create_file`，创建缺少最后一个 `}` 的 `HelloAgent.java`；工具成功并记录 CREATE。
2. 模型调用 `execute_command`，用当前 JDK 的 `javac`/`java` 验证；首次 `javac` 退出码为 1，编译输出返回模型并记录第一条 `CommandReport`。
3. 模型调用 `view_file` 得到完整 SHA-256；随后用该版本调用 `edit_file` 追加 `}`，记录 EDIT。
4. 模型再次调用同一验证命令；退出码为 0，输出含 `HelloAgent`，记录第二条 `CommandReport`；第六个模型回合给出完成说明。运行终态为 COMPLETED，Agent 工具事件可观察。测试同时确认临时目录中存在源码和 class 文件。

参考 Agent4J 的 `ExecuteCommandTool`、`ExecuteCommandParam`、`CommandExecutionSkill`：保留 `execute_command` 和 `command` 参数，但修正“先同步 `readLine` 至 EOF、再调用 `waitFor(60s)`”的无界等待问题；增加相对 cwd、shell 选择、环境白名单、注册权限、输出上限、运行报告和取消清理。未复制参考实现源码。

## 验证

本机使用 JDK 21：

```text
JAVA_HOME=/opt/homebrew/opt/openjdk@21 mvn -q -pl my-world-ai-app -am -Dtest=ExecuteCommandToolTest,CodegenCommandLoopTest,CodegenServiceTest,FileToolsTest -Dsurefire.failIfNoSpecifiedTests=false test
JAVA_HOME=/opt/homebrew/opt/openjdk@21 mvn -q -pl my-world-ai-app -am -Dtest='*,!OpenAiChatGatewayTest,!OpenAiChatCancellationTest,!OpenAiChatAgentIntegrationTest' -Dsurefire.failIfNoSpecifiedTests=false test
```

两条命令均成功；排除三个本地 HTTP fixture 类的全项目回归也成功。命令测试覆盖成功、非零退出码、空输出、相对 cwd、环境白名单、无换行大输出、短时限超时、父取消直接进程；默认关闭命令工具时，伪造调用返回 `TOOL_NOT_FOUND` 且无副作用。当前普通沙箱内 `ProcessHandle.descendants()` 抛出 `Operation not permitted (sysctl failed)`，子进程测试会跳过，生产代码在该情况下回退为直接进程强制终止。

随后在允许进程枚举的本机执行环境运行相同的 S12 专项命令，`ExecuteCommandToolTest` 6/6 通过且无跳过；其中 `parentCancellationKillsChildProcess` 和 `timeoutKillsChildProcess` 验证后台子进程被回收。

随后在同一具备所需权限的本机环境运行完整 `JAVA_HOME=/opt/homebrew/opt/openjdk@21 mvn -q test`，74/74 测试通过、无跳过，包含原有本地 HTTP fixture。其他平台的 shell 只进行了参数选择单元测试，未声称实际执行通过；未调用真实供应商。

## 理解问题

1. 为什么把 `waitFor(60s)` 放在同步读完整个输出之后，不能保证命令总共只运行 60 秒？
2. `cwd` 和环境变量白名单分别约束了什么？为什么它们仍不能作为操作系统沙箱？
3. 首次 `javac` 退出码为 1 时，Agent 为什么应先查看实际错误和文件版本，再修改并重新验证，而不能只凭模型文本宣布成功？
